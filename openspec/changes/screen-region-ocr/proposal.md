# OCRTool 屏幕区域截图识别

## Why

设计书 §3.4 给出了截图 OCR 的流程图（隐藏主窗口 → 截屏 → 透明层 → 框选 → OCR），§36 将其列为第二阶段首个功能，§58 定为 v1.1。但流程图之外，设计书对截图功能**没有任何设计**：全文未出现「多显示器」「DPI」「缩放比例」的讨论。

这正是本变更的真实风险所在。调研公开实现可以看到两类普遍缺陷：

- 大量实现直接用 `primaryScreen()` 截屏，多显示器下副屏区域全部错位；
- 少数实现改用虚拟桌面整屏截取，但整张截图只携带**一个** `devicePixelRatio`。当两台显示器缩放比例不同（例如 4K@150% + 1080p@100%，Windows 上极常见）时，单一比例不可能同时正确，必然有一块屏的选区映射是错的。

坐标映射错误的危害在于它**不会崩溃**：程序照常返回一段文本，只是识别的是用户没有框选的区域。这类缺陷在单显示器开发机上永远无法暴露，只会在用户机器上表现为「识别结果莫名其妙」。因此本变更把坐标正确性当作首要约束，而非附带细节。

## What Changes

### 屏幕捕获与选区

- 新增截图识别入口：主窗口触发后隐藏自身 → 捕获屏幕 → 展示选区界面 → 框选 → 识别。
- **采用冻结帧选区**：先完成屏幕像素捕获，再在静态画面上框选。选区期间屏幕内容变化（视频播放、通知弹出、光标闪烁）不影响捕获结果。
- **逐屏捕获、逐屏覆盖、选区不跨屏**：每块屏幕使用**自身**的缩放比例把逻辑坐标映射为物理像素。这既规避了混合 DPI 下单一缩放比例必然出错的问题，也避免了跨屏拼接产生像素密度不一致的图像——后者会直接损害识别质量。
- 明确取消语义：ESC、右键、以及面积过小的选区均视为取消，恢复主窗口且不产生识别请求，不按错误处理。
- 覆盖层生命周期受保护：无论正常完成、取消还是异常，覆盖层都必须销毁，不得在屏幕上残留。

### 与既有管线的衔接

- 捕获结果作为第四种图像输入接入 `image-input`，与打开文件 / 拖拽 / 粘贴走**同一条**识别管线：同样受最大边长限制并携带 `scale`，同样全程驻留内存不落临时文件（设计书 §44）。
- 不新增识别路径、不新增结果结构，`ocr-engine` 与 `ocr-execution` 的既有需求全部复用。

### 自动复制

- 新增可配置的识别结果自动复制（设计书 §36「自动复制」）。截图识别的价值在于「截 → 认 → 粘」闭环，缺少自动复制会退化为手动选中再 Ctrl+C。
- **空结果不得写剪贴板**：未检出文本时若仍执行复制，会用空字符串覆盖用户剪贴板中原有内容，属于破坏性行为。

## Capabilities

### New Capabilities

- `screen-capture`: 屏幕像素捕获、冻结帧区域选择、逐屏缩放比例还原、取消语义、覆盖层生命周期

### Modified Capabilities

- `image-input`: 新增屏幕区域捕获作为第四种图像输入方式
- `main-window`: 新增截图识别入口与识别结果自动复制

## Impact

- **依赖**：`mvp-image-ocr` 已完成。捕获结果复用 `image-input` 的尺寸限制与内存内数据流、`ocr-execution` 的请求序号与状态机
- **新增**：`src/ocrtool/capture/{screen_capture,region_overlay}.py`、`utils/clipboard.py` 扩展
- **新增配置项**：`ui.auto_copy`（布尔，默认开启）
- **修改**：`OCRTool_桌面OCR开发设计书.md` §3.4 需补全多显示器与 DPI 设计，§36 勾选「截图 OCR」「自动复制」
- **不包含**：全局快捷键触发截图（属 `background-residency`）、识别框绘制（属 `result-box-overlay`）、延时截图、窗口捕获、滚动截图
- **明确排除的技术路径**：Qt Multimedia 的 `QScreenCapture`——`packaging` 已规定 Multimedia 不得进入发布产物
