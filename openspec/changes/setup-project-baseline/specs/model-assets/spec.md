## Purpose

定义 OCR 模型文件在磁盘上的组织契约与解析规则，保证模型可独立于程序升级、可离线校验完整性，并保证程序在任何情况下都不会为获取模型而访问网络。

## ADDED Requirements

### Requirement: 模型目录契约

每个模型 MUST 以一个独立目录承载，目录内 MUST 包含描述文件、文本检测模型与文本识别模型。

#### Scenario: 合法的模型目录
- **WHEN** 系统扫描模型根目录
- **THEN** 同时包含描述文件、检测模型与识别模型的子目录被识别为一个可用模型

#### Scenario: 模型目录不完整
- **WHEN** 某个子目录缺少描述文件或任一模型文件
- **THEN** 该目录不被视为可用模型，并记录一条错误日志说明缺失的文件

#### Scenario: 多个模型并存
- **WHEN** 模型根目录下存在多个各自完整的模型目录
- **THEN** 它们全部被识别为可用模型，彼此互不影响

### Requirement: 模型标识与目录名解耦

模型的唯一标识 MUST 来自其描述文件中声明的标识符，MUST NOT 依赖目录名称。目录名称可自由包含版本信息。

#### Scenario: 按标识符定位模型
- **WHEN** 配置中指定了某个模型标识符
- **THEN** 系统定位到描述文件中声明该标识符的目录，无论该目录如何命名

#### Scenario: 标识符重复
- **WHEN** 两个模型目录的描述文件声明了相同的标识符
- **THEN** 系统判定模型集合非法，记录错误日志并向用户提示，不静默选择其中之一

### Requirement: 模型解析回退顺序

系统 MUST 按确定的顺序选择当前使用的模型。

#### Scenario: 配置指定的模型存在
- **WHEN** 配置中指定的模型标识符能在可用模型中找到
- **THEN** 采用该模型

#### Scenario: 配置指定的模型不存在
- **WHEN** 配置中指定的模型标识符找不到对应模型
- **THEN** 系统回退到描述文件中标记为推荐的模型，并记录一条错误日志

#### Scenario: 无推荐模型
- **WHEN** 没有任何模型被标记为推荐
- **THEN** 系统采用扫描到的第一个可用模型

#### Scenario: 无任何可用模型
- **WHEN** 不存在任何可用模型
- **THEN** 启动自检判定为失败，在界面状态区提示且记录错误日志；程序仍可启动，直到用户实际发起识别时才呈现明确的错误

### Requirement: 禁止为获取模型访问网络

系统 MUST NOT 在任何情况下自动下载模型文件。模型路径 MUST 被显式指定给推理组件，以阻断其内建的下载回退行为。

#### Scenario: 模型文件缺失
- **WHEN** 用户在模型缺失的情况下发起识别
- **THEN** 系统报告模型缺失错误，MUST NOT 尝试从网络获取模型

#### Scenario: 完全断网环境
- **WHEN** 运行环境无任何网络连接且模型文件完整
- **THEN** 识别功能正常工作，不产生任何网络请求

### Requirement: 模型文件完整性校验

模型获取过程 MUST 对文件内容进行哈希校验。

#### Scenario: 获取模型
- **WHEN** 通过获取流程落地一个模型文件
- **THEN** 该文件的 SHA256 与预先登记的期望值比对一致后才被采纳

#### Scenario: 校验不通过
- **WHEN** 落地文件的 SHA256 与期望值不符
- **THEN** 该文件被删除，流程以失败告终并说明原因，MUST NOT 保留不可信文件

#### Scenario: 文件已存在且校验通过
- **WHEN** 目标文件已存在且哈希与期望值一致
- **THEN** 跳过获取，流程可重复执行而不产生副作用

### Requirement: 不启用文本方向分类

系统 MUST NOT 使用文本方向分类能力，模型目录 MUST NOT 要求提供方向分类模型。

#### Scenario: 模型目录不含方向分类模型
- **WHEN** 模型目录仅含检测与识别两个模型文件
- **THEN** 该模型被判定为完整可用，识别功能正常工作

#### Scenario: 配置项不存在
- **WHEN** 用户查看配置文件
- **THEN** 其中不存在方向分类相关的开关项，避免暗示该能力可被开启
