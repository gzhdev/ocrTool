# app-paths Specification

## Purpose

为应用提供唯一的文件位置解析入口，区分「随程序分发的只读资源」与「运行期产生的可写状态」，使程序即使被安装在只读位置（如 Program Files、只读网络盘）也能正常运行。

## Requirements

### Requirement: 只读资源与可写状态使用独立的根目录

系统 MUST 将文件位置划分为两个独立的根：只读资源根（模型、默认配置、界面资源）与可写状态根（用户配置、日志、缓存）。两者 MUST 可以指向不同的物理位置。

#### Scenario: 解析只读资源位置
- **WHEN** 系统请求模型目录、默认配置或界面资源的位置
- **THEN** 返回的路径位于只读资源根之下，且该根始终为程序自身所在目录

#### Scenario: 解析可写状态位置
- **WHEN** 系统请求用户配置、日志或缓存的位置
- **THEN** 返回的路径位于可写状态根之下，该根由启动期探测决定

### Requirement: 启动期探测可写状态根

系统 MUST 在启动早期探测程序所在目录是否可写，并据此确定可写状态根与存储模式。

#### Scenario: 程序目录可写
- **WHEN** 程序所在目录可以成功写入文件
- **THEN** 存储模式为 Portable，可写状态根等于程序所在目录

#### Scenario: 程序目录不可写
- **WHEN** 程序所在目录写入失败（权限不足或介质只读）
- **THEN** 存储模式为 Installed，可写状态根为当前用户的本地应用数据目录下的 `OCRTool` 目录

#### Scenario: 探测必须基于实际写入
- **WHEN** 执行可写性探测
- **THEN** 探测通过实际创建并写入一个临时文件完成，MUST NOT 仅依据操作系统的权限位查询结果判定

#### Scenario: 探测不留残留
- **WHEN** 可写性探测结束（无论成功或失败）
- **THEN** 探测过程创建的临时文件已被清除

### Requirement: 可写状态根支持显式覆盖

系统 MUST 支持通过环境变量 `OCRTOOL_DATA_DIR` 显式指定可写状态根，该指定的优先级高于自动探测。

#### Scenario: 覆盖值有效
- **WHEN** `OCRTOOL_DATA_DIR` 已设置且指向可写位置
- **THEN** 可写状态根采用该值，自动探测被跳过

#### Scenario: 覆盖值无效
- **WHEN** `OCRTOOL_DATA_DIR` 已设置但不可写或无法创建
- **THEN** 启动失败并向用户说明具体原因，MUST NOT 静默回退到自动探测结果

### Requirement: 路径解析先于日志初始化完成

系统 MUST 在日志系统初始化之前完成可写状态根的确定，以保证启动期故障可被记录。

#### Scenario: 日志初始化时机
- **WHEN** 日志系统开始初始化
- **THEN** 可写状态根与存储模式已确定，日志文件被写入最终位置而非临时位置

### Requirement: 文件访问不依赖当前工作目录

系统的所有文件访问 MUST 经由路径解析获得绝对路径，MUST NOT 依赖进程的当前工作目录。

#### Scenario: 从任意工作目录启动
- **WHEN** 用户从任意工作目录启动程序（例如从其他磁盘的命令行调用）
- **THEN** 程序定位模型、配置、日志的行为与从程序目录启动时完全一致

### Requirement: 可写目录按需创建

系统 MUST 在首次访问前确保可写状态根下的子目录存在。

#### Scenario: 首次运行
- **WHEN** 可写状态根下的用户数据、日志或缓存目录不存在
- **THEN** 系统自动创建这些目录后再继续，不因目录缺失而失败
