# app-logging Specification

## Purpose

定义日志的落地位置、轮转策略与隐私边界，使程序故障可被诊断的同时，绝不将用户识别的文本内容写入磁盘。

## Requirements

### Requirement: 日志写入可写状态根并自动轮转

系统 MUST 将日志写入可写状态根下的日志目录，并对日志文件大小加以限制。

#### Scenario: 日志落地位置
- **WHEN** 系统写入日志
- **THEN** 日志文件位于可写状态根下的日志目录，而非程序所在目录（除非二者相同）

#### Scenario: 日志文件超出上限
- **WHEN** 当前日志文件达到 5 MB
- **THEN** 系统轮转日志文件，最多保留 3 个历史文件，更早的文件被删除

### Requirement: 启动时记录运行环境

系统 MUST 在启动时记录足以复现问题的环境信息。

#### Scenario: 程序启动
- **WHEN** 程序完成初始化
- **THEN** 日志中包含应用版本、操作系统版本、运行时版本、推理执行提供者、推理线程数、存储模式与可写状态根的实际路径

### Requirement: 识别内容不得写入日志

系统 MUST NOT 将 OCR 识别出的文本内容或原始图像数据写入日志，无论日志级别如何设置。

#### Scenario: 识别完成后记录
- **WHEN** 一次识别成功完成
- **THEN** 日志仅包含图像尺寸、识别行数与耗时，不包含任何识别出的文本

#### Scenario: 第三方组件尝试输出识别内容
- **WHEN** 底层 OCR 组件自行输出包含识别内容的日志
- **THEN** 该输出被系统抑制，不出现在日志文件与标准输出中

#### Scenario: 调试级别下的约束
- **WHEN** 日志级别被设置为 DEBUG
- **THEN** 识别文本与图像内容依然不被记录

### Requirement: 异常完整记录但不直接呈现给用户

系统 MUST 将异常的完整技术细节写入日志，MUST NOT 将其原样展示在用户界面。

#### Scenario: 发生未预期异常
- **WHEN** 程序运行中抛出异常
- **THEN** 日志中包含异常类型、消息与调用栈，用户界面仅显示一条可读的中文说明

### Requirement: 日志级别可配置

系统 MUST 支持通过配置调整日志级别，默认为 INFO。

#### Scenario: 调整日志级别
- **WHEN** 配置中将日志级别设为 DEBUG 并重启程序
- **THEN** DEBUG 级别的日志被记录
