# packaging Specification

## Purpose

定义 OCRTool 发布产物的形态、内容边界与验收标准，保证终端用户在没有任何开发环境的 Windows 机器上解压即可运行，且模型可独立于程序升级。

## Requirements

### Requirement: 发布产物为免安装目录包

发布产物 MUST 是一个解压即用的目录，MUST NOT 要求用户执行安装程序或预先安装运行环境。

#### Scenario: 用户获取并运行
- **WHEN** 用户在 Windows 10/11 x64 上解压发布包并双击可执行文件
- **THEN** 程序正常启动并显示主界面，全程无需安装 Python、CUDA、.NET SDK 或其他开发环境

#### Scenario: 发布目录结构
- **WHEN** 用户查看解压后的目录
- **THEN** 可执行文件与模型目录、默认配置目录、用户数据目录、日志目录、缓存目录、运行时目录处于同一层级

### Requirement: 模型与默认配置外置于运行时

模型文件与默认配置 MUST 位于可执行文件同级的独立目录中，MUST NOT 被封装进运行时目录。

#### Scenario: 替换模型
- **WHEN** 用户以新的模型目录替换发布包中的模型目录
- **THEN** 程序在下次启动时使用新模型，无需重新打包程序

#### Scenario: 模型位置可见
- **WHEN** 用户查看发布目录
- **THEN** 模型文件以普通文件形式存在于模型目录中，可被直接检视与替换

### Requirement: 禁止组件不得进入发布产物

发布产物 MUST NOT 包含浏览器引擎、多媒体、声明式界面与三维图形等本项目不使用的界面框架组件。

#### Scenario: 检视产物内容
- **WHEN** 对发布产物执行内容清点
- **THEN** 其中不存在 WebEngine、Multimedia、Qml、Quick、3D、Charts 相关的库文件

### Requirement: 发布产物中只存在一套界面框架运行时

发布产物 MUST NOT 包含由第三方依赖间接引入的第二套界面框架平台插件。

#### Scenario: 启动产物
- **WHEN** 用户启动打包后的程序
- **THEN** 程序正常显示窗口，不出现界面框架平台插件加载失败或冲突导致的启动崩溃

### Requirement: 第三方推理组件的运行期数据文件完整

发布产物 MUST 包含第三方 OCR 组件在运行期所需的非代码文件。

#### Scenario: 打包产物首次识别
- **WHEN** 用户在打包产物中首次发起识别
- **THEN** 识别正常完成，不因第三方组件的配置文件或字符字典缺失而失败

### Requirement: 发布包命名与版本一致

发布包 MUST 采用 `OCRTool-<version>-win-x64.zip` 命名，其中版本号 MUST 与程序内声明的版本一致。

#### Scenario: 核对版本
- **WHEN** 用户比对发布包文件名、程序启动日志与界面中显示的版本号
- **THEN** 三处版本号完全一致

### Requirement: 发布包不含构建与运行残留

发布包 MUST NOT 包含构建过程或冒烟验证产生的日志、缓存与用户配置。

#### Scenario: 检视新解压的目录
- **WHEN** 用户解压全新的发布包
- **THEN** 日志目录、缓存目录与用户数据目录为空

### Requirement: 发布前必须通过冒烟验收

发布流程 MUST 包含在无开发环境的目标机器上对产物的端到端验证，验证不通过 MUST NOT 发布。

#### Scenario: 冒烟验收
- **WHEN** 在未安装 Python 的 Windows 10/11 x64 机器上解压产物、启动程序并识别一张中英混合样本图
- **THEN** 程序成功启动、输出识别文本、正常退出，且退出后未在程序目录之外留下预期以外的文件
