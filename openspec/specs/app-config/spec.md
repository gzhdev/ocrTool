# app-config Specification

## Purpose

定义配置的来源、优先级与持久化规则，保证用户设置在程序升级后仍然有效，并保证配置文件损坏时程序仍可启动。

## Requirements

### Requirement: 配置按三层优先级合并

系统 MUST 按「内置默认值 → 随程序分发的默认配置文件 → 用户配置文件」的顺序加载配置，后加载者覆盖先加载者的同名项。

#### Scenario: 三层均提供同一配置项
- **WHEN** 同一配置项在内置默认值、默认配置文件与用户配置文件中都有取值
- **THEN** 最终生效的是用户配置文件中的取值

#### Scenario: 用户配置缺少某项
- **WHEN** 用户配置文件中不含某配置项
- **THEN** 该项回落到默认配置文件的取值；若默认配置文件也不含该项，则回落到内置默认值

#### Scenario: 默认配置文件缺失
- **WHEN** 随程序分发的默认配置文件不存在
- **THEN** 系统使用内置默认值继续启动，并记录一条错误日志

### Requirement: 首次运行生成用户配置

系统 MUST 在用户配置文件不存在时基于默认配置生成一份。

#### Scenario: 首次启动
- **WHEN** 用户配置文件不存在
- **THEN** 系统以默认配置为内容创建用户配置文件，后续启动优先读取该文件

### Requirement: 程序升级不得覆盖用户配置

用户配置 MUST 独立于随程序分发的文件，程序目录被整体替换后用户配置仍然有效。

#### Scenario: 替换程序目录后启动
- **WHEN** 用户以新版本的程序目录替换旧版本，随后启动程序
- **THEN** 此前保存的用户配置项依然生效，无需用户手工迁移任何文件

### Requirement: 配置损坏时降级而非失败

系统 MUST NOT 因用户配置文件损坏而无法启动。

#### Scenario: 用户配置文件无法解析
- **WHEN** 用户配置文件内容不是合法 JSON 或结构不符合预期
- **THEN** 系统将损坏文件另存备份、以默认配置继续启动、记录错误日志，并在界面状态区提示用户配置已重置

### Requirement: 未识别的配置项予以保留

系统 MUST 在写回用户配置时保留自身不认识的配置项。

#### Scenario: 读到更高版本写入的配置
- **WHEN** 用户配置文件中包含当前版本不认识的配置项，且系统需要写回配置
- **THEN** 这些配置项在写回后依然存在，不被丢弃
